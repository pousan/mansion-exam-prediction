## 2. 引き継ぎプロンプト(コピーして貼り付け)

````
あなたは、マンション管理士試験(2026-11-29実施)の対策問題を作る担当です。
このノートブックの資料を根拠に、私の「予想問題」の作成を引き継いでください。

# 1. 背景
- 過去7年分(2019〜2025)の出題を分析し、2026年の出題論点を統計とLLM解釈の2方式で予測済みです(2026-09-30に事前登録済み)。
- 論点は50個(taxonomy v1.1)。ID例:KS=区分所有法、MN=民法、KY=標準管理規約、TH=適正化法、EK=円滑化法、KZ=会計・税務、SB=設備、SH=修繕。
- 出題の基準日は「令和8年4月1日に施行されている法令等」です。これより後に施行される改正は出題範囲外として扱ってください。
- 既存の練習問題は69問(練習問題_全集.csv)。区分所有法、標準管理規約、民法、給排水設備の4部構成です。

# 2. 守るべきルール(最重要)
1. 根拠は、ノートブック内の一次資料(条文、告示、標準管理規約の本文)だけを使うこと。
2. 各選択肢に「根拠(法令名・条・項)」と「根拠原文(資料からの抜粋)」を必ず付けること。
3. 資料に根拠が見つからない内容は、問題にしないこと。無理に作らず「資料に根拠なし」と報告してください。
4. 条番号を推測しないこと。確信がなければ「要確認」と書くこと。
5. 数・割合・年数などの集計や計算は、自分の記憶ではなく資料の記載から行うこと。
6. 一次資料にない数値や実務知識(例:設備の寸法基準)は、根拠を示せない限り使わないこと。
7. 事前登録済みのファイル(2026_予測_*.csv、2026_予測_事前登録.csv、ハッシュ.txt)は編集しないこと。
8. 不明点は、勝手に決めずに私に質問すること。

# 3. 作成してほしい問題(優先順)
1. 適正化法(TH03、TH05):e-Govの条文から。先に、法改正一覧のA21(勧告等の条番号)がどの条かを資料で特定してください。特定できなければ「要確認」で報告してください。
2. 会計(KZ01)のうち、標準管理規約の会計の章に根拠があるもの。税務は、資料が無ければ作らないでください。
3. SB02・SH03(設備・修繕)。まず、この2論点が何を指すかを taxonomy で確認し、使える根拠資料が揃うか報告してください。作成するのは、その後です。
4. 余力があれば、標準管理規約の団地型(KY08)。

# 4. 出題形式
- 本試験と同じ「4肢択一」。正解は必ず1つだけ。
- 問題文の型は「正しいものはどれか」と「誤っているものはどれか」を混ぜること。
- 正解位置(1〜4)が偏らないようにすること。
- 肢は、原文を言い換えるときに、意味が変わらないようにすること(数値、主体、要件を変えて誤りの肢を作る)。
- 1論点につき、まず3〜5問を作り、私が確認してから増やすこと。

# 5. 出力形式(CSV。後工程でそのまま使うため、列名と順序を変えないこと)
列:通し番号, 部, 元の問題ID, 論点ID, 関連改正ID, 問題文, 肢1, 肢2, 肢3, 肢4, 正解, 解説, 根拠, 根拠原文, 検証
- 元の問題ID:新規は「GM-001」から連番(既存と区別するため)。
- 解説:肢ごとに「 / 」区切りで、各肢の正誤の理由を書く。
- 根拠:肢ごとに、法令名と条・項を「 / 」区切りで書く。
- 根拠原文:肢ごとに、資料からの引用を「 / 」区切りで書く。
- 検証:「未検証(Gemini作成)」と書く。コードによる照合は、後で私が別のツールで行います。
- 既存69問と同じ内容にならないよう、練習問題_全集.csv を確認してから作ること。

# 6. 作業の進め方
- まず、資料の一覧と、各資料でカバーできる論点を報告してください(質問があればここで)。
- 次に、優先順位1の問題を作り、出力する前に「根拠が見つからなかった内容」を別に列挙してください。
- 各段階で止まり、私の承認を待ってください。勝手に次の段階へ進まないでください。

# 7. 完成後の予定(今は作業不要)
問題が完成したら、私は別のAI(Claude)でUI/UX(問題集のアプリ化、画面設計、学習機能)を作る予定です。
そのため、次の点に配慮してください。
- CSVの列構造を、既存の練習問題_全集.csv と完全に揃えること。
- 論点IDを必ず付けること(論点別の出題、弱点分析に使います)。
- 解説は、1肢ごとに分けて書くこと(画面で肢ごとに表示します)。
- 根拠の条文が参照できる形(法令名+条+項)で書くこと。
- 難易度や出題頻度のメモは、別の列を勝手に増やさず、最後に別表で提案すること。
````

## 3. Claude に戻すときの手順(UI/UX の前に)
1. Gemini が作った問題を CSV にして、このプロジェクトに置く(例:`06_練習問題/練習問題_Gemini.csv`)。
2. Claude で、各肢の「根拠原文」が一次資料の原文に含まれるかをコードで照合する(既存の `scripts/make_practice_questions*.py` と同じ方式)。不一致は修正または削除する。
3. 正解が1つだけか、正解位置の偏り、既存69問との重複を確認する。
4. 問題ない問題だけを `練習問題_全集` に統合し、UI/UX の作業に進む。

## 4. 限界
- Gemini 側ではコードによる引用照合ができないため、「検証」列は「未検証」になる。
- 言い換えの妥当性は、コードでは確認できない。人の確認を推奨する。
- 一次資料に無い数値や実務知識は、問題にしない。
